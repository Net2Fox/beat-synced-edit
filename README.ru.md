# Beat-Sync Edit для Claude Code и Codex

[English](README.md) · **Русский** · [Все возможности](docs/capabilities.ru.md)

Создавайте эдиты из своих видео и фотографий под музыку, описывая нужный
результат в Claude Code или Codex. Этот **форк Net2Fox** дополняет
[оригинальный проект ZiadAbdelkarim](https://github.com/ZiadAbdelkarim/beat-synced-edit)
сохраняемым монтажным проектом, точной длительностью, монтажом по речи,
микшированием звука, локальной анимированной графикой, отслеживанием объектов,
субтитрами и управляемым замедлением.

Скилл подходит для TikTok, YouTube Shorts, Reels, роликов о путешествиях,
автомобильных эдитов, игровых хайлайтов и видео о товарах. Он монтирует
существующие материалы, а не генерирует новые кадры. Python-инструменты можно
запускать напрямую, без агента.

## Что можно сделать

| Возможность | Как работает |
|---|---|
| Монтаж под музыку | Оценка уверенности битов, монтаж по фразам при слабом ритме, исправляемые музыкальные события и ускорительные speed ramps с резервированием исходника. |
| Разговорные шортсы | Выбор законченных фраз, сохранение смысловых пауз и исходной речи под B-roll; исправляемые слова и импорт перевода. |
| Звук | Исходный звук, речь, музыка и SFX, плавные входы/выходы, приглушение музыки под речь, измерение громкости и перестановка музыки по тактам. |
| Смешанные материалы | Объединение видео и фотографий из отдельных файлов, папок и ZIP-архивов. |
| Подбор кадров по содержанию | Проверенные аннотации, объяснение оценок и альтернативы, запрос и предпочтения, история принятых/отклонённых кадров. |
| Кадрирование | Вертикальный, квадратный или горизонтальный формат; диагностика трекинга, ручные ключевые кадры камеры, фиксированный кроп и вписывание с полями. |
| Графика | Сохраняемые стили и безопасные зоны текста, локальные карточки, счётчики и слои, которые рендерятся в повторно используемый MP4. |
| Стилизация и акценты | Семь настраиваемых пресетов (в том числе phonk, anime и travel), восемь вариантов цветокоррекции, переходы на склейках (вспышка, затемнение, whip, глитч, RGB, размытие, зум), короткие зумы, тряска, пульсация под бит, зерно, виньетка, свечение, кашетирование и движение фотографий. |
| Управление скоростью | По умолчанию — воспроизведение со скоростью не ниже 1×. Замедление только по прямому запросу, с интерполяцией по оптическому потоку. |
| Текст | Анимированные титры, оформление субтитров, импорт/экспорт SRT/VTT и дополнительное локальное распознавание речи с подсветкой слов. |
| Правки | Сохранение проекта, предпросмотр, замена и перестановка кадров, редактирование текста и повторное использование кеша неизменённых кадров. |
| Экспорт и проверка | MP4 H.264/AAC, проверка декодирования/звука/чёрных кадров, контактные листы и пакетный рендер с общим кешем кадров. |

В [полном описании возможностей](docs/capabilities.ru.md) разобраны все
поддерживаемые сценарии, различия пресетов, примеры и практические ограничения.

## Требования

- **Claude Code или Codex с доступом к локальным файлам и командам** — для
  монтажа через диалог. Для работы только через CLI не нужны ни агент, ни
  ключ API.
- **Python 3.12 или новее.** Проверено на Windows с Python 3.12 и на Linux
  с Python 3.13; на macOS используются те же POSIX-команды.
- **FFmpeg и ffprobe в PATH**, с поддержкой кодирования H.264 (`libx264`) и AAC.
  Сборку для своей системы можно найти на
  [странице загрузки FFmpeg](https://ffmpeg.org/download.html).
- Локальные исходники, музыкальный трек и место для импортированных материалов,
  предпросмотров и кеша. Для титров и субтитров нужен шрифт с поддержкой нужных
  символов Unicode; если системный шрифт их не содержит, укажите путь к TTF/OTF.

Базовое окружение использует librosa, PySceneDetect, OpenCV, NumPy, SciPy
и Pillow (около 0,7 ГБ). Распознавание речи устанавливается отдельно и
работает через Faster Whisper. Видеокарта не обязательна: распознавание по
умолчанию использует CPU/int8, а рендеринг и интерполяция выполняются локально.

## Установка скилла

Скилл — это вся папка [`skills/beat-sync-edit`](skills/beat-sync-edit):
`SKILL.md`, `scripts/`, `references/`, файлы зависимостей и лицензия.
Если скопировать только `SKILL.md`, у скилла не будет инструментов.

### Claude Code

Скопируйте папку в `~/.claude/skills/beat-sync-edit`, чтобы скилл был доступен
во всех проектах, или в `<проект>/.claude/skills/beat-sync-edit` — для одного
проекта, затем настройте окружение (ниже). Это может сделать сам Claude Code:

```text
Установи скилл из https://github.com/Net2Fox/beat-synced-edit
(папка skills/beat-sync-edit) в ~/.claude/skills/beat-sync-edit.
Создай внутри .venv, установи его requirements.txt и проверь установку
командой scripts/edit_project.py doctor через этот интерпретатор.
```

В этом репозитории есть и синхронизированная копия
`.claude/skills/beat-sync-edit`, поэтому Claude Code, открытый внутри
репозитория, подхватывает скилл без установки.

### Codex

Отправьте Codex такой запрос:

```text
$skill-installer Install the skill from
https://github.com/Net2Fox/beat-synced-edit/tree/main/skills/beat-sync-edit
Create a .venv inside the installed skill directory, install its requirements.txt,
and run scripts/edit_project.py doctor with that interpreter to check the setup.
Tell me the installed path.
```

Для ручной установки скопируйте папку в `~/.agents/skills/beat-sync-edit`
(для себя) или `<проект>/.agents/skills/beat-sync-edit` (для одного
репозитория); некоторые установщики используют `$CODEX_HOME/skills` (обычно
`~/.codex/skills`). Не создавайте дубликатов и перезапустите Codex, если скилл
не появился. См. [документацию OpenAI о скиллах](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills).

### Настройка окружения

Создайте окружение один раз внутри установленной папки и дальше используйте
её `.venv`. Замените путь в примере на фактическую папку установки.

**Windows / PowerShell**

```powershell
$skillRoot = 'C:/path/to/installed/beat-sync-edit'
python -m venv (Join-Path $skillRoot '.venv')
$editPython = Join-Path $skillRoot '.venv/Scripts/python.exe'
& $editPython -m pip install -r (Join-Path $skillRoot 'requirements.txt')
ffmpeg -version
ffprobe -version
& $editPython -X utf8 (Join-Path $skillRoot 'scripts/edit_project.py') doctor
```

**macOS / Linux**

```sh
skillRoot='/path/to/installed/beat-sync-edit'
python3 -m venv "$skillRoot/.venv"
editPython="$skillRoot/.venv/bin/python"
"$editPython" -m pip install -r "$skillRoot/requirements.txt"
ffmpeg -version
ffprobe -version
"$editPython" -X utf8 "$skillRoot/scripts/edit_project.py" doctor
```

`doctor` выводит JSON-отчёт о готовности (Python, пакеты, кодеки FFmpeg и
шрифт для субтитров) с исправлением для каждой проблемы и завершается с кодом 0,
когда всё обязательное готово, и с кодом 4 в противном случае. В `warnings`
попадают необязательные пункты, требующие внимания (PyAV 19+, шрифт, запуск не
из `.venv` скилла); с `--strict` ошибкой считаются и они, и отсутствие
распознавания речи. К каждой подсказке приложен `fix_argv` — те же команды в
виде списков аргументов. Он работает и до установки
зависимостей, поэтому при любой ошибке запускайте его первым; если запустить
его другим Python, он выведет команды, которые создают и наполняют `.venv`
скилла.

`requirements.txt` устанавливает актуальные совместимые версии.
`requirements.lock.txt` фиксирует окружение, проверенное на Windows
с Python 3.12 (зависимости для распознавания речи в нём не учтены). Чтобы
установить именно эти версии, используйте его как ограничение:

```powershell
& $editPython -m pip install -r (Join-Path $skillRoot 'requirements.txt') -c (Join-Path $skillRoot 'requirements.lock.txt')
```

```sh
"$editPython" -m pip install -r "$skillRoot/requirements.txt" -c "$skillRoot/requirements.lock.txt"
```

### Автоматические субтитры — по желанию

Попросите агента установить `requirements-transcription.txt` в то же окружение
или выполните сами с интерпретатором из примера выше:

```powershell
& $editPython -m pip install -r (Join-Path $skillRoot 'requirements-transcription.txt')
```

```sh
"$editPython" -m pip install -r "$skillRoot/requirements-transcription.txt"
```

Веса модели Whisper скачиваются при первом запуске. По умолчанию используется
многоязычная `small`; `tiny` подходит для быстрой проверки, а модели с суффиксом
`.en` поддерживают только английский язык. Каждая модель скачивается один раз
в общий кеш пользователя (`~/.cache/beat-sync-edit/models`; на Windows
`%LOCALAPPDATA%\beat-sync-edit\models`) и используется всеми проектами.
Другую папку задают переменной `BEAT_SYNC_MODEL_DIR` или параметром
`--model-dir`; если кеш недоступен для записи, модели сохраняются в `models/`
рядом с проектом.
Для `--local-files-only` модель уже должна быть в кеше или локальной папке.
Распознавание обрабатывает звук локально и не отправляет его в сервис
транскрибации. Сам агент следует собственным настройкам обработки данных
моделью и инструментами. Для ручных титров и файлов SRT/VTT Whisper не нужен.

### Обновление существующей установки

Новые версии удаляют файлы, которые были в прежних (например,
`references/legacy-workflow.md`, `scripts/render_edit.py` и `UPSTREAM.json`),
поэтому при копировании новой папки поверх старой они останутся. Сделайте
резервную копию установленного скилла, удалите в нём всё, кроме `.venv` и
своих папок, скопируйте новую папку `skills/beat-sync-edit` и установите
изменившиеся зависимости. Один лишь `git pull` в репозитории не обновляет
отдельно скопированный скилл.

```sh
skillRoot='/path/to/installed/beat-sync-edit'
newSkill='/path/to/beat-synced-edit/skills/beat-sync-edit'
rm -rf "$skillRoot/SKILL.md" "$skillRoot/UPSTREAM.json" "$skillRoot/scripts" "$skillRoot/references"
cp -R "$newSkill/." "$skillRoot/"
"$skillRoot/.venv/bin/python" -m pip install -r "$skillRoot/requirements.txt"
```

```powershell
$skillRoot = 'C:/path/to/installed/beat-sync-edit'
$newSkill = 'C:/path/to/beat-synced-edit/skills/beat-sync-edit'
'SKILL.md','UPSTREAM.json','scripts','references' | ForEach-Object { Remove-Item -Recurse -Force -ErrorAction SilentlyContinue (Join-Path $skillRoot $_) }
Copy-Item -Recurse -Force (Join-Path $newSkill '*') $skillRoot
& (Join-Path $skillRoot '.venv/Scripts/python.exe') -m pip install -r (Join-Path $skillRoot 'requirements.txt')
```

## Использование

Откройте локальную рабочую папку и укажите агенту пути к видео, фотографиям
и музыке. Задайте длительность, соотношение сторон, желаемый стиль и моменты,
которые нужно включить или исключить. Рабочие файлы попадут в `work/`, а
готовые ролики — в `outputs/`, если не выбрать другие папки. Claude Code
подхватывает скилл по запросу (или наберите `/beat-sync-edit`); в Codex начните
запрос с `$beat-sync-edit`.

**Первый эдит**

> Сделай эдит на 25 секунд из видео в этой папке под этот трек: 9:16,
> 1080×1920, 30 FPS, склейки в бит и короткие зумы на дропе. Сохрани
> естественные цвета и не повторяй кадры. Экспортируй MP4.

**Короткий ролик из речи**

> Сделай из этого интервью вертикальный ролик на 45 секунд из самых сильных
> законченных ответов, с вшитыми субтитрами.

**Титры и субтитры**

> Добавь титр «Новое начало» на первые две секунды. Распознай русскую речь
> в итоговой звуковой дорожке, сделай короткие субтитры с тёмной подложкой
> и жёлтой подсветкой слов. Экспортируй MP4 и SRT.

**Правка готового монтажа**

> Возьми этот project.json. Замени третий кадр крупным планом, убери вспышки,
> исправь второй субтитр и сохрани общую длительность.

**Прямой запрос на замедление**

> Замедли момент удара до половинной скорости с интерполяцией кадров.
> Остальные кадры оставь на обычной скорости или быстрее.

Замедление **выключено по умолчанию**, в том числе в пресетах и при нехватке
исходников. Для него нужны прямой запрос в вашем промпте и интерполяция по
оптическому потоку. Простое растягивание временных меток, снижение FPS
воспроизведения, замедление дублированием кадров и обычное смешивание кадров
запрещены. Если интерполяция не сработала, рендеринг останавливается и не
переходит к обычному замедлению. Оптический поток всё же может давать артефакты
при перекрытии объектов или быстром движении, поэтому результат нужно проверить.

## Как это работает

1. **Индексация материалов.** Проверка файлов, поиск сцен, оценка движения
   и яркости, создание листов с миниатюрами и сохранение распакованных ZIP.
2. **Просмотр содержания.** Агент или монтажёр изучает исходные кадры и
   добавляет теги объектов, крупность планов и временные метки действий.
   Статистические характеристики изображения сами по себе не распознают
   объекты и не объясняют сюжет.
3. **Анализ музыки.** Поиск битов и изменений энергии, затем оценка музыкальных
   частей. Начало музыкального фрагмента и границы частей можно задать вручную.
4. **Сохранение плана.** Создание непрерывной монтажной последовательности
   с диапазонами исходников, кадрированием, эффектами и точным числом
   выходных кадров в `project.json`.
5. **Предпросмотр и правки.** Рендер MP4 уменьшенного размера и локальной
   HTML-страницы для просмотра. Страница экспортирует JSON с правками,
   но сама не сохраняет изменения в проект и не запускает рендеринг.
6. **Рендеринг и проверка.** Обработка и кеширование отдельных кадров монтажа,
   наложение текста, добавление выбранной звуковой дорожки и проверка
   итогового MP4 через ffprobe.

Храните `project.json`, исходники и распакованные материалы вместе. В проектах
используются абсолютные пути к медиафайлам: при перемещении файлов эти пути
нужно обновить. Предыдущие версии сохраняются в `.history/`; основной CLI
по умолчанию кеширует кадры монтажа в `cache/` рядом с проектом
(обычно `work/cache/`). Правки только текста используют готовый кеш изображения,
но итоговое видео всё равно требует наложения текста и кодирования.

## Использование из командной строки

CLI работает и без агента. Как и в `SKILL.md`, `edit_project.py` ниже означает
`<python> -X utf8 <skill>/scripts/edit_project.py`, где `<skill>` — папка
установленного скилла (или `skills/beat-sync-edit` в клоне), а `<python>` —
интерпретатор из её `.venv`. Замените пути к исходникам на свои.

```sh
edit_project.py analyze /path/to/footage --work work/library
edit_project.py music /path/to/song.wav --duration 25 -o work/beats.json
edit_project.py plan --library work/library/library.json --beats work/beats.json --duration 25 --preset cinematic --grade none --size 1080x1920 --fps 30 -o work/project.json
edit_project.py preview work/project.json -o work/preview.mp4
edit_project.py render work/project.json -o outputs/edit.mp4
```

Для подбора кадров по содержанию изучите листы с миниатюрами и примените
аннотации **до** команды `plan`; иначе выбор будет опираться на доступные
технические метаданные. Переходы, акценты и оформление — это операции `revise`
над сохранённым проектом; `edit_project.py effects` выводит каталог, а
[справочник эффектов](skills/beat-sync-edit/references/effects-and-looks.md)
сопоставляет с ними запросы вроде «вспышки между клипами» или «киношно». В [руководстве по проектам](skills/beat-sync-edit/references/project-workflow.md)
описаны JSON-аннотации, музыкальные части, разрешение замедления и правки.

Команды для текста работают с сохранённым проектом. Выберите **либо** импорт
готового файла субтитров, **либо** распознавание звука: каждая операция заменяет
дорожку субтитров с сохранением предыдущей версии:

```sh
edit_project.py title work/project.json --text "Новое начало" --start 0 --end 2 --animation fade
edit_project.py subtitles-import work/project.json /path/to/captions.srt --preset boxed
# Вместо импорта, после установки дополнительных зависимостей для распознавания:
edit_project.py subtitles-transcribe work/project.json --language ru --model small --preset karaoke
edit_project.py subtitles-export work/project.json -o outputs/captions.vtt
edit_project.py render work/project.json -o outputs/captioned.mp4
```

Доступные параметры перечислены в `edit_project.py --help` и
`edit_project.py <command> --help`. Настройки оформления, сдвиги времени, кеш
моделей и временные метки слов описаны в
[руководстве по тексту и графике](skills/beat-sync-edit/references/text-and-graphics.md).

## Результат и ограничения

- Длительность округляется до одного выходного кадра: 25 секунд при 30 FPS —
  это 750 кадров. При нехватке исходников возникает ошибка либо используются
  разрешённые альтернативы; планировщик не вводит незапрошенное замедление
  или повторы и не сокращает заданную длительность ради нехватки материала.
- Музыкальные проекты звучат выбранной дорожкой; звук исходных клипов
  добавляется, только если `audio-config` включает `source_audio` или
  добавляет дорожки. Речевые проекты по умолчанию сохраняют исходную речь.
  Файл `--audio` для `subtitles-transcribe` используется только для
  распознавания и в монтаж не добавляется.
- Субтитры встраиваются в изображение MP4. Отдельные SRT/VTT содержат текст
  и время показа, но не анимацию и подсветку слов; переключаемых дорожек
  субтитров в MP4 нет.
- Музыкальные части, трекинг и распознанный текст нужно проверять. Речь
  и слова песен могут распознаваться с ошибками, а высокое разрешение или
  FPS экспорта сами по себе не восстанавливают качество плохих исходников.
- Нет автоматической публикации на платформах, генерации видео, синтеза
  голоса и встроенного перевода субтитров. Страница предпросмотра не заменяет
  полноценный редактор монтажной последовательности.

## Решение проблем

| Проблема | Что проверить |
|---|---|
| Скилл не отображается | Проверьте, что папка установлена целиком в обнаруживаемый каталог; удалите дубликаты; при необходимости перезапустите агента. |
| Ошибка импорта или зависимостей | Запустите `edit_project.py doctor` интерпретатором из `.venv` скилла: он перечислит, чего не хватает, и команду установки. |
| FFmpeg не запускается или не кодирует | Проверьте наличие обеих программ в PATH и поддержку `libx264`/AAC; `doctor` проверяет всё это. |
| Не хватает исходников | Добавьте неиспользованные клипы или фото, сократите длительность либо прямо разрешите повторы. Для замедления нужен отдельный прямой запрос. |
| Субтитры пустые или не совпадают со звуком | Проверьте слышимую звуковую дорожку, её начало, систему отсчёта и сдвиг времени субтитров, выбранный язык. |
| В тексте отсутствуют символы | Укажите абсолютный путь `--font` к подходящему шрифту Unicode в формате TTF/OTF. |
| Модель распознавания недоступна без интернета | Сначала скачайте модель в кеш или укажите путь к существующей модели в конвертированном формате. |

`skills/beat-sync-edit` — единственный источник скилла: `SKILL.md`,
`references/` и `scripts/` редактируются только там.
`.claude/skills/beat-sync-edit` — генерируемая копия для Claude Code; после
каждого изменения обновляйте её командой `tools/sync_skill.py` (пока копия
устарела, юнит-тесты падают). Окружение для разработки ставится из
`skills/beat-sync-edit/requirements.txt`; проверки запускайте этим
интерпретатором при доступном FFmpeg:

```sh
python tools/sync_skill.py
python -X utf8 -m unittest discover -s tests -p "test_*.py"
python -X utf8 tests/project_smoke_test.py
python -X utf8 tests/text_smoke_test.py
python -X utf8 tests/music_editorial_smoke.py
python -X utf8 tests/motion_smoke_test.py
python -X utf8 tests/finishing_tools_smoke_test.py
```

Сквозные проверки создают синтетические материалы в игнорируемых Git папках
`work/`. Личные исходники и скачивание речевых моделей для них не нужны.
Каждая сквозная проверка принимает `--scripts-dir`, чтобы тестировать
установленную копию. Это локальные проверки, а не заявление о покрытии всех
платформ в CI. Синтетические примеры не доказывают качество распознавания
реальной речи, удержание личности в кадре или художественное качество монтажа.
